# Ironveil: notes for agents

Browser stealth-tank game (TypeScript, Vite). **Main mode: missions in a 3D isometric Three.js view.**
Setting (docs/SETTING.md): our Slavic, Soviet-leaning Vostrava vs the Germanic Directorate of Graustein, both
fictional. Never give the enemy Nazi/WWII symbolism.
Secondary: 2D Phaser "Skirmish" team deathmatch (the original game). Read README.md for the player view.
The owner prefers conservative scope, polish over breadth, and honest effort estimates.

**Design and content work: read [docs/WORKFLOW.md](docs/WORKFLOW.md) first.** The owner gives the feel, the vision and
piece-by-piece critique; the agent is expected to generate the middle (premise, arrangement, map, script, lines)
with its own creative liberty and hand over something playable to judge, not a questionnaire or a plan.

## Commands

```bash
npm test            # vitest, all suites must stay green
npm run typecheck   # tsc --noEmit (strict, noUnusedLocals)
npm run build       # typecheck + vite build
npm run dev         # http://localhost:5173
```

## Invariants (do not break)

- `src/sim`, `src/ai`, `src/game`, `src/level` are headless: no Phaser, DOM or client imports
  (enforced by `tests/architecture.test.ts`). AI never imports `sim/world`.
- Renderers draw from the player team's `Observation` only, never from `World` directly, so hidden
  enemies never reach the screen. The one exception is deliberate: the 3D HUD reads the garrison
  AI's alert state for enemies that are *already visible*, to draw ?/! markers.
- The sim is deterministic at 30 Hz; presentation interpolates `prevObs → obs` by `session.alpha`.
- Levels and missions are validated on load and in tests (`tests/greybox.test.ts` validates every
  registered mission). Add new content to the registry and the tests cover it.
- Commit attribution lines are supplied by the harness; never put model names in code or commits.

## Gotchas

- Mission/level JSON imports are cast to their types in `src/content/missions/index.ts` (JSON
  widens string literals); runtime validation is the real check.
- `Surface` enum values in `three/materials.ts` are baked into GLSL `#if` branches; don't renumber.
- The frame's passes are in `three/post.ts` (no EffectComposer). Ambient occlusion reads the scene's own
  depth texture, so anything that writes depth gets AO: see-through effects (mist, cones, sprites, decals)
  must keep `depthWrite: false`, or AO wraps around them. See D35.
- Static scenery is merged per material and per map tile (`mergeStatic`/`ChunkMerger`) so it can be
  culled; anything that must move or change per frame (lamp bulbs via shared material colour, tanks) stays separate.
  Use `roundedBox()` (`three/geometry.ts`), not `new RoundedBoxGeometry`: three's is a triangle soup. See D37.
- **Shadows are cast by stand-in meshes, not by what you see** (D34). Merged scenery has `castShadow = false`;
  its positions-only copies are on `SHADOW_LAYER`. Things that move put a stand-in on `SHADOW_DYNAMIC_LAYER`
  (`Parts.build` does it for tanks); a caster that is also drawn in the view (the debris InstancedMesh) *enables*
  that layer as well as layer 0. Shadow cameras look at both layers; the view camera at neither.
- A new moving shadow caster needs three things, or its shadow goes stale or missing: the dynamic layer (above),
  a pose check in `trackCasters` (`view.ts`), and a position in `view.casters`. `trackCasters` feeds both the lamp
  pool (`three/lamps.ts`, `shadow.autoUpdate = false`, maps redraw only for casters that *moved* and for blasts)
  and the moon. Light counts never change at runtime (shader recompiles). See D30.
- The moon's shadow map is filled by `three/moonshadow.ts`: scenery cached in its own depth target, copied in
  around the moving casters, which are drawn on top. Its frustum moves in steps; don't position the moon elsewhere.
  Short-lived effect lights request from the shared `GlowLights` pool (fx.ts) each frame; never add a PointLight. See D32.
- `materials.ts` patches three's `lights_fragment_begin` chunk at import (lights out of reach skip the BRDF) and
  owns two noise textures every surface shader reads (`uNoise` lattice, `uFbm` pre-summed). A three.js upgrade
  that rewords the chunk or `RoundedBoxGeometry` fails `tests/shader-patch.test.ts` / `rounded-box.test.ts`. See D36.
- Don't read `clientWidth`/`getBoundingClientRect` per frame (forces a layout after the HUD's writes): the view
  caches its size in `resize()`. HUD elements are looked up once (`Hud3D.el`); enemy markers are kept per enemy.
- Garrison barks (`BARK_LINES` in `ai/simple.ts`) are not radio: the 3D HUD draws them as callouts
  over visible speakers and `Radio.bark` plays them panned. Line choice must not draw from the AI RNG.
- Crew radio goes through `Comms` (three/comms.ts), which owns the queue and timing and calls
  `audio.transmit` when a line goes on air. Don't play radio lines from anywhere else, or text and voice
  drift apart. Portrait SVG parts (`.head .eyes .brows .m0/.m1/.m2`) are animated by CSS classes.
- Explosions, debris, wreck fires and damage smoke live in `three/blast.ts`; all sprites, chunks and
  lights are pooled up front so fights never create materials or change the light count (shader recompiles).
  Garrison tanks have `GARRISON_HP` (60, `game/mission/session.ts`); tanks carry `maxHp`, so never assume 100.
- `V` toggles the performance telemetry overlay (`three/telemetry.ts`); it sets `renderer.info.autoReset = false`.
- Playtest perf log (`three/perflog.ts`): in the owner's preview artifact the game writes 2 s samples and
  stutters to the artifact's private db (`perf/<session>` + `perf/<session>/chunks/<n>`, rules: admin only).
  Read them with ArtifactData (`list` collection `perf`, then the chunks). Does nothing outside the artifact.
  The preview must keep `capabilities: {db: {rules: [{path: "perf", read: "admin", write: "admin"}]}, user: {}}`
  (omit `capabilities` on republish to keep it).
- Audio only starts after a user gesture (`audio.unlock()` on first pointer/key). `audio.tap()`
  exposes the final mix for recording previews.
- Debug hook in the browser: `window.__ironveil` → `{ game, hud, settings, audio, mission(), view() }` (`view().aim` is the world point under the cursor).
  Headless screenshots: Playwright + SwiftShader; the sim runs in slow motion there, so tests
  teleport the player via `__ironveil.mission().world.tank(0).pos`.
